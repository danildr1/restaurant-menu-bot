# VK FAQ-бот

Бот отвечает на личные сообщения сообщества VK, используя содержимое
`knowledge_base.md`. Он не должен дополнять базу догадками: при отсутствии
информации предлагает обратиться к сотруднику.

## Запуск

1. Создайте сообщество VK и в разделе «Управление → Работа с API» создайте
   ключ доступа с правами на сообщения.
2. В разделе «Сообщения» включите сообщения сообщества, а в «Long Poll API» —
   Long Poll и событие `message_new`.
3. Скопируйте `.env.example` в `.env` и заполните переменные.
4. Заполните `knowledge_base.md` достоверной информацией.
5. Установите зависимости и запустите бота:

   ```bash
   cd vk_faq_bot
   pip install -r requirements.txt
   python bot.py
   ```

## Развёртывание на Render

Создайте новый Background Worker из этого репозитория. В качестве blueprint
можно выбрать `vk_faq_bot/render.yaml`; затем задайте секретные переменные из
`.env.example`. Текущий сервис Telegram-бота не меняйте: это отдельный worker.

## Обновление FAQ

Редактируйте `knowledge_base.md`. Файл перечитывается перед каждым сообщением,
поэтому после перезапуска или деплоя новые ответы начинают использоваться сразу.

## Гости без автоответов

Добавьте числовые VK ID постоянных гостей в `silent_users.json`. Для них бот
полностью отключит автоответы, а менеджеры продолжат вести диалог вручную:

```json
[123456789, 987654321]
```

Файл перечитывается перед каждым сообщением, поэтому изменения действуют сразу.

## Временная передача диалога менеджеру

Если бот не понял сообщение, он направляет гостя к менеджеру и перестаёт
отвечать в этом диалоге на 24 часа. Активные паузы хранятся в
`muted_dialogs.json`, поэтому не сбрасываются после перезапуска бота. По
истечении 24 часов бот автоматически снова отвечает гостю.
